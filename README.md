# シカクログ

資格試験の受験者数・合格率・試験制度を、実施団体の公表資料から**出典つきで**1ページにまとめるサイト。
あわせて、合格した人の勉強時間や使用教材の自己申告データを集めている。

https://shikaku-log.com

## このリポジトリについて

サイトの全コードを公開している。企画・調査・設計・実装・運用をAI(Claude)が主導し、
その過程を記録しながら進めるプロジェクトの成果物。

## 設計上の約束

このサイトはデータが信用できることだけが取り柄なので、以下を仕組みで守っている。

### サンプル数が20件に満たなければ統計値を出さない

数件しかない状態の中央値は、投稿が1件増えるだけで大きく動く。
その数字が「相場」として一人歩きすると、かえって読む人の判断を誤らせる。

閾値の判定は表示側でなく集計ロジック(`src/lib/metrics.ts`)で強制していて、
テンプレートが独自に緩めることはできない。

### 公式統計とユーザー投稿を混ぜない

実施団体が公表した数値と利用者の自己申告は、色と枠線で区別して表示する。
同じグラフの中に並べることもしない。投稿データには必ず「自己申告」の注記と件数(n)を添える。

### 出典を後付けしない

数値には実施団体の公表ページへのリンクと取得日を付ける。
リンク先で確認できない数値・記述は載せない。1つのURLで複数の項目をまとめて根拠づけることもしない
(受験資格・問題数・手数料はたいてい別ページにある)。

### 投稿がゼロでも成立する

公式統計・試験日程・制度情報の層だけで、資格情報サイトとして価値がある構造にしている。
ユーザー投稿は上積みであって、前提ではない。

### 統計・公式情報はJavaScriptに依存させない

学習ペース逆算ツールの対話部分だけがJS。統計・制度情報・チャートはすべてサーバ側で
静的HTMLとして出力するため、JSを無効にしても情報価値が保たれる。

## 構成

| 技術 | 用途 |
|---|---|
| [Astro](https://astro.build/) | 静的生成 |
| Cloudflare Pages | ホスティング |
| Cloudflare D1 | 投稿データ |
| Pages Functions | 投稿API |

維持費はドメイン代のみ。それ以外は無料枠で動かしている。

## 開発

```bash
npm install
npm run dev      # 開発サーバ
npm run build    # ビルド
npm run qa       # 公開前の自動チェック(これが通らないものはデプロイしない)
```

### `npm run qa` が検査するもの

| 分類 | 内容 |
|---|---|
| 秘匿情報 | ASP ID・APIキーの混入(このリポジトリは公開されている) |
| SEO | title/descriptionの重複、h1の数、canonical |
| 法務 | 広告を含むページのPR表記、投稿データの「自己申告」注記 |
| リンク | 内部リンク切れ、孤立ページ |
| 薄いページ | 固有の情報を持たないページの検出 |
| 禁止表現 | 誇大表現(「必ず合格」等)とAI定型文 |
| 差し替え忘れ | プレースホルダのまま公開されるのを防ぐ |

ERROR が1件でもあれば終了コード1で落ちる。人の注意力に頼らず機械で止める方針。

### 検索トラフィックの記録

```bash
npm run metrics             # 週次スナップショット(Search Console も一緒に取る)
npm run gsc                 # Search Console だけ取り直す
npm run gsc -- --inspect    # sitemap の各URLがインデックスされているかも数える
npm run gsc -- --print      # 記録せず表示だけ
```

表示回数・クリック数・平均掲載順位・上位クエリは Search Analytics API から取る。
以前は管理画面を見て手で書く欄にしていたが、手作業の工程は急いでいるときに必ず飛ばされる。
`npm run metrics` の中に入れて飛ばせなくしてある。

`npm run qa` は次の3つを見る。**「0」と「取れていない」を別のものとして扱う。**

| 状態 | 扱い |
|---|---|
| 表示回数が `null` | WARN — 取得の設定が壊れている(数字の話ではない) |
| 表示回数が 0 | WARN — 届いていない |
| 3週続けて 0 | ERROR — ページを増やす前に届け方を直す |

認証情報は `.env` に置く(`.gitignore` 済み)。サービスアカウントの鍵を使う場合:

```
GSC_SERVICE_ACCOUNT_FILE=/path/to/key.json
# 任意。ドメインプロパティなら sc-domain:shikaku-log.com
# GSC_SITE_URL=https://shikaku-log.com/
```

Google Cloud でサービスアカウントを作って鍵(JSON)を落とし、Search Console の
「設定 > ユーザーと権限」でその `client_email` を**制限付き**ユーザーとして追加する。
OAuth を使う場合は `GSC_CLIENT_ID` / `GSC_CLIENT_SECRET` / `GSC_REFRESH_TOKEN` を置く。
認証情報が無いときは取得を飛ばすだけで、週次の記録そのものは止まらない。

## 掲載データについて

- 公式統計は各実施団体の公表資料から取得している。出典URLと取得日は各ページに明記
- 制度は改定されることがある。出願前には必ず実施団体の最新の案内を確認してほしい
- 合格報告は利用者の自己申告であり、公的な統計ではない
- 掲載内容の誤りを見つけたら[お問い合わせ](https://shikaku-log.com/contact/)から教えてほしい

## ライセンス

コードの利用については未定。掲載データの著作権は各実施団体に帰属する。
